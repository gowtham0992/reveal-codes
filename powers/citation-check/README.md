# Citation check, a Kiro Power

This Power checks the legal citations and quotations in a document against CourtListener, inside Kiro. It reports each citation as found, found but a different case, not found, or could not be checked. It checks each quotation attributed to a cited case against the opinion text. It also answers what a federal court or judge requires about AI in filings, from a bundled dataset of published court instruments.

It is part of [Reveal Codes](../../README.md). It works in any Kiro workspace.

## Import it

1. In Kiro, open the Powers panel and choose Add Custom Power.
2. Choose Import power from a folder and select this folder (`powers/citation-check`), or choose Import power from GitHub and give the repository URL, `https://github.com/gowtham0992/reveal-codes`.

Node 20 or newer must be on the path. Nothing else is installed: the server is one file, `server/courtlistener-mcp.mjs`.

## Set the token

CourtListener refuses citation lookups without a token. To check live, create a free CourtListener API token and put it in an environment variable in the shell that starts Kiro:

```sh
export COURTLISTENER_TOKEN=your-token
```

Never put the token in a file. The Power's `mcp.json` only refers to the variable.

## The two modes

- **Live.** With a token, the server checks each citation against CourtListener.
- **Fixtures.** Without a token, or with an empty or unexpanded `${...}` value, the server answers from recorded CourtListener responses bundled in `server/fixtures/`. It knows the Reveal Codes demo motion and the citations from Mata v. Avianca, and nothing else. In this mode a citation reported as not found may still exist. `verifier_status` says which mode is in use.

## Three things to ask

- Check the citations in this file.
- Is 556 U.S. 662 really Henderson v. Pacific Housing Authority?
- What does the Northern District of Texas require about AI in filings?

In fixtures mode, the second question answers that the citation is a different case, Ashcroft v. Iqbal (2009).

## What it will not do

- It will not propose a replacement for a citation it cannot find.
- It will not say whether a case supports a point. It checks that the case exists, that the name matches, and that quoted words appear in the opinion.
- It will not mark a citation as fine when it could not be checked.
- It answers court rules only from the bundled dataset. Where a court is not in it, the Power says so.
- It is not legal advice.

## What is in this folder

| Path                           | What it is                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `plugin.json`, `mcp.json`      | The manifest and the MCP server configuration.                                        |
| `server/courtlistener-mcp.mjs` | The built server. Generated by `pnpm power:build`; do not edit it.                    |
| `server/fixtures/`             | A copy of `packages/verifier/fixtures`, the recorded responses used in fixtures mode. |
| `skills/check-citations/`      | The procedure for checking a document, and the list of statuses and codes.            |
| `skills/court-ai-rules/`       | The procedure for court rules, and a copy of `data/standing-orders.json` (CC0).       |

After a change to the verifier, the MCP server or the dataset, run `pnpm power:build` and commit the result. A test fails when the committed files differ from a fresh build.
