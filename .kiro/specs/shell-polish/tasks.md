# Implementation Plan: shell-polish

## Overview

The plan polishes the visual shell of `apps/web` in four groups, in the order of Requirement 15.5: toolbar and hook scope, status line and mode text, page and side regions, then window identity, dialogs, scan, docs and the final checkpoint. It changes layout, labels and text placement only. The Store, the Verify flow, the Export flow, the Pane contents, the Engine, the Verifier and the Export_Package are not changed, and no dependency is added.

Task count: **12 tasks**, counted as leaf sub-tasks (numbered `N.M`), the final checkpoint included (4.5). The four group headings are not counted. The dependency graph lists the 11 non-checkpoint leaves. The design has no Correctness Properties, so there are no property tasks and no optional (`*`) tasks. Every test is an example test, written inside the task that builds the code, together with the updates to existing tests that the change breaks, so the suite is green after every task.

Conventions that apply to every task:

- Paths are repository-relative. Source modules stay at 300 lines or fewer and functions at 40 lines or fewer. No `any`, named exports only outside Next `page`, `layout` and `route` files, no `try/catch` that swallows (tech.md).
- Tasks touching `apps/web` follow ui.md: no component, icon or CSS library, one global stylesheet plus one CSS module per component, palette `#FFFFFF`, `#111111`, `#B0B0B0`, `#ECECEC` with accent `#1F3A8A` only for focus and links, no shadows, radius, gradients or transitions, text labels only, no exclamation marks, no toasts. Fonts only through the three family variables, weights 400 or 700. The static scans in `apps/web/test/static` enforce this.
- No `vi.mock` beyond what already exists, nothing mocks the Engine or the Verifier, no property test, no snapshot test. Tests use the existing helpers `renderUi`, `modeApi`, `createManualTimers` and `createMemoryStorage`.
- jsdom does not compute CSS modules. Visual rules (type, rules, dimensions) are covered by the Css_Scan and by the browser walk in the final checkpoint, and each task says only that it writes them.
- The Css_Scan rejects any font size outside its accepted list in every CSS module. Task 1.1 and task 2.1 therefore each add the one size they introduce to the `sizes` list in `apps/web/test/static/css-rules.test.ts` (a one-line change each) so the suite stays green. Task 4.3 completes the scan change of Requirement 13.6 and 13.7.
- `docs/KIRO_USAGE.md` is edited only in task 4.4. Tasks that change the hook script or `ui.md` do not touch it.
- Task completion notes record anything Kiro got wrong and the fix, for the BUILD_LOG entry in task 4.4.
- No file under `packages/engine`, `packages/verifier`, `packages/export` or `packages/courtlistener-mcp` is edited, no `package.json` dependency field changes, the lockfile does not change, and the README screenshot placeholder is not touched (Req 15.3, 15.4).
